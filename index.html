04 myDATA Integration

No native Zoho–myDATA integration exists. The entire myDATA layer must be built as a custom integration within Zoho Creator, communicating with AADE's API. This is a legal requirement — the integration operates as an invisible backend process within the Zoho environment.

Regulatory timeline: Phase 1 (revenue >€1M) became mandatory 2 March 2026. Phase 2 (all others) becomes mandatory 2 November 2026. From 1 February 2027, direct ERP transmission is no longer accepted — a certified provider is required.

Zoho One bundles may offer better economics at scale.

10 Open Questions & Prerequisites

Before development begins, the following must be resolved. Items marked Blocking prevent work on dependent modules.

Blocking Certified e-invoicing provider selection
Which provider has AFS selected or shortlisted? The entire myDATA and e-invoicing integration depends on the provider's API specification, authentication method, sandbox availability, and pricing model. If no provider has been selected: evaluate based on API quality (REST/JSON preferred), sandbox availability, Zoho-compatible authentication (OAuth 2.0 or API key), Greek market coverage, and pricing per transmission. The start declaration for Phase 2 (deadline 2 November 2026) requires identifying the provider. Has this been filed?
Blocking Chart of Accounts
Does AFS have a standard CoA template for all clients, or does each client maintain its own? Is the CoA based on ΕΓΛΣ (older) or ΕΛΠ (current)? We need the CoA-to-E3 mapping for at least one representative client to build and validate the E3 classification engine.
Client portfolio scope
How many organizations in the first phase? Are all clients Greek-domiciled or are there cross-border operations requiring multi-currency / intra-community VAT?
Existing data & migration
Are clients migrating from Pylon or another ERP, or starting fresh? If migrating: opening balances, outstanding invoices, fixed asset registers, and historical myDATA submissions need import paths. Is there historical myDATA data in AADE that needs reconciliation from day one?
Infrastructure & environment
Confirm the Zoho data center region for all organizations (EU expected — crm.zoho.eu). Confirm Creator and Analytics availability per subscription. Verify API rate limits support expected daily transaction volume (especially month-end closing).

Where Option A wins:
  • Time-to-compliance: Leverages a certified accounting engine rather than building one from scratch.
  • Foundation reuse: Builds on the existing CRM Logistirio module and Creator sync infrastructure already in production for IASIS.
  • Maintenance scope: Core accounting updates (VAT rates, regulatory changes) are handled by Zoho; only the Greek layer needs custom maintenance.
  • Existing infrastructure: The bidirectional CRM ↔ Creator sync, external partner upload flows, and pharmaceutical tracking modules remain untouched.
  • Onboarding simplicity: Standard Zoho Books interface for day-to-day bookkeeping; custom components only for Greece-specific workflows.
  • Ecosystem integration: Native connections to Zoho Analytics, Zoho Expense, Zoho Inventory, and 50+ other Zoho apps without custom API work.
Where Option B makes sense: A full custom Creator app is the right choice when the client's accounting requirements are so specialized that Books cannot accommodate them (e.g., fund accounting for complex financial instruments), the client will never use Books' standard features, or the client needs absolute control over every UI element and has the engineering team to maintain it indefinitely.

12 Recommendation & Next Steps

Option A (Zoho Books + Creator Greek Accounting Layer) is the recommended architecture. It delivers full Greek accounting compliance within the Zoho ecosystem, meets the AFS scope requirements, respects the Phase 2 timeline, and builds on the existing IASIS infrastructure.

The Greek Accounting Layer in Creator is not a workaround — it is the correct architectural pattern: let the best-in-class tool handle what it does well, and build the localization and compliance logic as a modular, maintainable, reusable layer alongside it.
